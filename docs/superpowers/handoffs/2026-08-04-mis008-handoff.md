## 5. Metodologia de revisão

### 5.1 Os cinco veredictos por campo

Todo campo de tela recebe exatamente um:

| veredicto | significado |
|---|---|
| **VIVO** | mostra o que promete, com produtor real medido |
| **ÓRFÃO** | tem produtor, ninguém consome |
| **FANTASMA** | a tela mostra, nada produz o valor |
| **MENTIRA** | mostra um número que não é o que o rótulo diz |
| **MUDO** | falha sem sinal — a tela fica verde com o dado errado ou ausente |

### 5.2 Cadeia de prova — elo por elo

Elo sem prova é elo que já falhou em silêncio nesta casa.

| elo | lane | controle negativo nomeado |
|---|---|---|
| payload do provider → DTO | `unit` | fixture sem o campo, prova que vira desconhecido e não zero |
| DTO → domínio | `unit` | valor errado no fixture, prova que a asserção reprova |
| domínio → banco | `integration` (`//go:build integration` nas 5 primeiras linhas) | must-fail com `failure_token=test=` citado |
| banco → API | `integration` | schema shape, não só presença |
| API → tela | `browser` | live-drive dirigido pelo operador |
| leitura Oracle | `live-oracle` | somente leitura, `METALPRD` |
| leitura do provider | `live-provider-read` | controle positivo injetado |

**Critério de aceite falsificável:** todo critério é **um comando com saída esperada** ou
**uma string na tela**. Nunca um adjetivo.

Regras herdadas e medidas: verde de integração só é evidência **depois que o vermelho nomear
o teste**; asserção de presença não pega valor errado; a lane hermética **não** é superconjunto
da de unidade.

### 5.3 Governança — o veredito é um diff de conjunto

Invariantes de governança são relações. O único critério sólido é o **diff de conjunto de
`(error_code, id, path)` entre base e head, com o mesmo instrumento nos dois lados**.

```bash
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/harness.ps1 -Command governance -BaseSha <40-hex>
```

Sem `-BaseSha` de 40 hex a lane devolve `GOV_SEMANTIC_DRIFT`/`base-sha-invalid`. Base do gate
de **merge** é o **tip do alvo**, não a base de despacho — senão um chip velho apaga feature
da `main` no merge e o diff não vê.

Quatro armadilhas com o código do erro:

1. `GOV_PRODUCTION_PANIC` — `panic` fora de teste. Existem `mustRat` **baselineados**; copiar
   o padrão para arquivo novo **não herda a exceção**
2. `GOV_MIGRATION_PREFIX` — fatias paralelas colidem no mesmo número. Quem despacha em
   paralelo **reserva o prefixo**
3. `GOV_MODULE_DEPENDENCY` — importar `modules/<alvo>/<camada>` exige `<alvo>` em
   `dependencies` de `contracts/governance/modules.json`. Importar `domain`/`ports` de outro
   módulo é permitido pela regra de camada; **a aresta ainda precisa ser declarada**
4. `GOV_MODULE_LAYER` — importar `adapters`/`transport`/`registry` alheios exige
   `temporary_exceptions` com `path` + `import_path` **exatos**

O `id` da issue é `"$source-$target"` mas o `path` é o **arquivo**: um arquivo novo numa
aresta já violada gera **linha nova** no diff de conjunto. Herdar violação por proximidade é
o mesmo erro do `panic`.

## 6. Padrão de arquitetura da casa

Terceiro é terceiro; a plataforma traduz para o modelo nativo. Postgres **não** é terceiro —
é o estado canônico nosso.

| exigência | exemplo aprovado |
|---|---|
| SQL/códigos do fornecedor ficam no adapter | `internal_read/adapters/oracle/icms_matrix.go:39-44` |
| adapter devolve tipo do domínio | `:94` → `domain.ICMSMatrixCell` |
| porta sem vocabulário do fornecedor | `pricing/ports/tax_matrix.go` |
| domínio puro | `pricing/domain/icms.go:3` importa só `math/big` |
| contrato checado em compile-time | `matrix_reader.go:12` — `var _ ports.X = (*Y)(nil)` |
| dinheiro exato | `big.Rat` + `::text` no SQL, nunca round-trip `float64` |

**Mirror-first, ratificado:** Oracle só alimenta o sync; as telas leem **só** do Postgres.
Polling em camadas, sem delta/CDC.

**Direção da dependência:** `sync` é o relógio, `dependencies: []`, e não conhece nenhum
domínio. Cada módulo depende do `sync`, nunca o contrário. O corpo do job mora no módulo dono
do dado; o que fica no `sync` é só a entidade no enum, que é a chave de `sync_state`.

**Vazamento conhecido e ainda aberto (A-1):** `internal_read/domain/icms_matrix.go:16` —
`TgficmRow` carrega nomes de coluna do Sankhya e `ResolveCell:113-127` decide sobre os
literais `"I"`/`"N"`/`"S"`, códigos de restrição do fornecedor. Regra de negócio escrita no
dicionário do ERP: inútil no dia do segundo ERP. Correto = adapter traduz para candidato
neutro, domínio decide sobre o neutro. **Nenhuma lane pega isso.** Fatia própria, depois de os
números do live drive baterem.

## 8. Armadilhas medidas — ler antes de gastar uma hora nelas

1. **B-8, wedge de shell.** Assinatura:
   `` /usr/bin/bash: -c: line NN: unexpected EOF while looking for matching `' ``. Mata a
   sessão inteira, subagentes inclusos. Probe: rodar `true`; se falhar, o shell morreu e a
   única saída é sessão nova. Contornos que funcionam enquanto o shell está vivo: um comando
   curto por chamada, nunca `&&`/`;` encadeados; mensagem de commit escrita com a ferramenta
   Write em `.git/CMSGn` + `git commit -F`; SQL escrito em arquivo, `docker cp`, `psql -f`
2. **Binário velho faz o live drive mentir.** Comparar `Created` do container com o horário do
   primeiro commit da fatia **antes** de acreditar em qualquer número
3. **`schema_migrations` é chaveado por NOME DE ARQUIVO** (`platform/migrate/runner.go:98`).
   Renomear migração já aplicada faz o runner reaplicá-la — DDL idempotente e `ON CONFLICT`
   no seed, nunca cirurgia manual no ledger
4. **`psql` sem usuário quebra** com `FATAL: role "postgres" does not exist`. Usar
   `docker exec … sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" …'`
5. **Nomes de coluna não se adivinham.** O join de pedidos↔produtos é
   `products_mirror.codigo_produto` (text) contra
