## The five heaviest, with detail

**1. Money as float64 outside the two exact-decimal systems (G-1).** `internal/kernel/exact` (banned-float64, `Decimal` type) and `pricing/domain/decimal.go` (`Money{Amount string}` + `big.Rat` via `ParseRat`/`FormatRatHalfUp`) are two independently-built exact-decimal engines. Neither is float64. But `orders`, `profitability`, and `marketplaces` never adopted either: their domain types are `*float64` for every money field (`order_decomposition.go:11-105`, `input.go:114-121`), and arithmetic happens directly on the float (`internal/modules/orders/application/enrich_service.go:455` `sum += *item.SaleFeeAmount * float64(item.Quantity)`; `:473` similarly for cost). One crossing point is carefully guarded — `internal/modules/orders/adapters/pricingtax/reader.go:266` `lineTotal` rejects any `float64` that is not the faithful image of a 2dp decimal (verified by reading the function; it round-trips through `big.Rat`/`FormatRatHalfUp` and compares) — but that guard exists at exactly one adapter boundary. Every other float64 field in `orders`/`profitability` is read, summed, and serialized with no equivalent check. `profitability/application/service.go:676,772` (`revenueAmount`, `extendUnitCost`) do the same raw `*float64 * float64(int)` multiplication with no guard. This is a hazard by the lane's own rubric (any float64 in a money path), and it is large: 78 files, 373 occurrences, spanning three modules' domain layers, not isolated adapter noise.

**2. Clock injection is a coin flip by module (G-2).** `orders/application/{import_service.go:41,ingest_service.go:48,orders_job.go:55}`, `product_links/application/{batch_service.go:85,generation_service.go:63,import_service.go:38,resolution_service.go:119}`, `profitability/application/service.go:71`, and `inventory/application/manual_action_facade.go:42` all use the same idiom: a constructor parameter `now func() time.Time` that defaults to `func() time.Time { return time.Now().UTC() }` only when nil, making every timestamp-bearing code path replaceable in tests. `integrations/application/auth_flow_service.go:161-168` goes further with a named `authFlowClock` interface and a `systemAuthFlowClock{}` default — the most rigorous version of the same idiom. But five other `integrations` services (`auth_service.go`, `capability_service.go`, `credential_service.go`, `installation_service.go`, `operation_service.go`) and `classifications/application/service.go` call `time.Now()` inline with no override point at all — `CreatedAt`/`UpdatedAt` on every row these services write cannot be pinned in a test. `classifications/application/service.go` additionally drops `.UTC()` (`:46,74`), the only file in this sample that does, against a codebase-wide UTC convention visible everywhere else the pattern was checked (`auth_flow_service.go:280,318,374,516,557,613,655,761,825`, `provider_operation_service.go:59`, `assisted_sankhya_linkage_service.go:72`, etc.). Same file also has `credentialID` generation bypass the injected clock at `auth_flow_service.go:812` (`fmt.Sprintf("cred_%d", time.Now().UTC().UnixNano())`), even though the surrounding service otherwise routes every timestamp through `s.clock.Now()`.

**3. Declared panic set matches actual panics exactly — a genuine "what's fine" that is also worth stating loudly (cross-referenced against G-5/dead-code and the invariants file).** `grep -rn "panic(" internal | grep -v _test.go` → exactly 8 occurrences, all in `internal/kernel/exact/decimal.go:84,141`, `internal/kernel/fact/knowledge.go:134`, `internal/modules/pricing/domain/decompose.go:308`, `internal/modules/pricing/domain/difal.go:79,83`, `internal/modules/product_links/application/resolution_service.go:752`, `internal/platform/apierror/recover.go:29`. `contracts/governance/invariants.json` declares exactly these under `production-panic-*` exceptions (7 entries, one — `kernel-fact-mustvalue` — double-declared for a CRLF/LF fingerprint variant, both matching the same physical site), and each carries a `reason` + `removal_owner`. `cmd/` has zero panics. This is a closed set with no drift — the rare case in this audit where the declared exception list and the measured reality are identical to the occurrence.

**4. Interfaces are overwhelmingly consumer-defined, matching the repo's own rule.** `ARCHITECTURE.md:185` ("The module owns the port interfaces; adapters implement them") and `:39` (ADR-033, ports owned by the consuming context) are followed in measurement: 141/280 (50%) of all interface declarations live under a `ports/` directory — the canonical hexagonal port, defined by the consumer, implemented elsewhere. 0 interfaces are declared in any `domain/` package (domain stays interface-free, consistent with the layering rule). Of the remaining 35 declared inside `adapters/` packages, 27 (77%) are unexported single-purpose local abstractions (`rowScanner`, `queryer`, `tokenGetter`) — the correct "accept interfaces, return structs" idiom scoped to the file that needs it, not a producer-defined surface other packages must import. Only 8 adapter interfaces are exported, and none of those were found to be re-implemented by more than the one adapter that declares them (spot-checked `Writer` in `internal_read/adapters/mirror/writer.go:69`, `Database` in `internal_read/adapters/oracle/database.go:11`).

**5. errgroup usage is bounded and race-free where it exists.** The only production `errgroup`/`WaitGroup` usage in the codebase is `internal/modules/orders/application/enrich_service.go:154-163` (`Enrich`, the order-list shipment-fetch fan-out). It sets an explicit concurrency limit (`g.SetLimit(shipmentConcurrency)`), writes into a pre-sized slice at a per-goroutine-fixed index (`shipments[i] = ...`, no shared-index race), captures loop variables correctly (`i, order := index, order`), and the `_ = g.Wait()` discard is safe because `g.Go`'s closure always returns `nil` (errors are handled inside `fetchShipment`, not surfaced through the group). No other goroutine spawn in `internal/` is per-request/unbounded; the rest are one-per-process background schedulers/tickers started once from `internal/composition/root.go` (`root.go:694-921`, 13 sites) or from module composition roots (`listings/composition/scheduler.go`, `orders/composition/scheduler.go`), all keyed to a long-lived `context.Background()` that is the correct choice for a daemon loop outliving any single request. `internal/platform/httpx/route_deadline.go:93-122` (per-request deadline middleware) is the one per-request goroutine spawn and uses the standard `context.WithTimeout` + goroutine + `select` idiom from the Go blog's canonical pattern.

## What is actually fine

- **Panic discipline is exact.** 8 panics in `internal/`, all declared in `contracts/governance/invariants.json` with a `reason` and `removal_owner`, 0 undeclared, 0 in `cmd/`. This is a closed, currently-accurate contract — do not touch the panic sites or the governance entries without updating both together.
- **`errors.Is`/`errors.As` discipline is real.** 120 + 37 = 157 uses against 42 declared sentinels; `fmt.Errorf("%w", ...)` outnumbers `"%v"` 355:12, and 11 of those 12 `%v` uses are deliberately formatting a non-error value (an entropy count, a recovered `interface{}`), not discarding a real error's identity.
- **`go vet ./...` and `go build ./...` are both clean** from a fresh `GOCACHE`, across the whole module.
- **Interfaces follow the repo's own rule.** 141/280 (50%) are in `ports/` (consumer-owned per `ARCHITECTURE.md:185`), 0 in `domain/`, and 77% of the smaller `adapters/`-local set are unexported single-purpose abstractions. This is the textbook Go pattern and should be the template for anything that currently lacks a port.
- **The one production `errgroup` use is correct**: bounded concurrency, indexed writes (no race), correct loop-variable capture, safe error discard because the callee swallows its own errors by design. `internal/modules/orders/application/enrich_service.go:154-163`.
- **The one guarded float64→decimal crossing is careful, not lucky.** `internal/modules/orders/adapters/pricingtax/reader.go:266` `lineTotal` explicitly rejects any float64 whose nearest 2dp decimal does not round-trip back to the same float, converting a would-be silent-wrong-answer into an honest "unknown." This is the model for what the other 373 float64 money sites don't have.
- **`json.Unmarshal` into bare `var m map[string]json.RawMessage`/`map[string]any` is the correct idiom** (8 sites checked) — Go allocates the map on decode, none of the sites write into the variable before unmarshalling, so there is no nil-map-write hazard in the sample checked.
- **Background goroutine lifecycle at the composition root is conventional for this shape of service** — one ticker/scheduler per long-running concern, started once at boot with `context.Background()` (correct: nothing shorter-lived to derive from), no per-request unbounded spawning found anywhere in `internal/`.
- **The route-class deadline middleware (`internal/platform/httpx/route_deadline.go`) is the textbook `context.WithTimeout` + goroutine + `select` pattern**, correctly buffers the response so a timed-out handler can't write a torn response, and documents (`:124-129`) a genuine import-cycle reason for a local constant instead of reusing `apierror`.

## Unverified / needs judgment

- **G-1 (float64 money) scale is a raw grep count (373/78 files), not a verified list of "this specific field is read/written/persisted as float64 with no downstream decimal guard."** A small number of these 373 are likely percentages, coordinates, or non-money floats (e.g. `internal/modules/divergences/domain/tolerance.go`, `internal/modules/catalog/domain/product.go` weren't individually classified) — the finding's order of magnitude is solid, the exact money-only subset is `unverified`.
- **G-3 (bare `fmt.Errorf` as `errors.New` substitute) was only confirmed in `classifications`; not swept across all 468 `fmt.Errorf` call sites** — doing so exactly would require checking each for verb presence, which this budget did not spend.
- **Dead-code sweep beyond the two established facts (11, 13) was not attempted.** No tool run (e.g. `deadcode`, `staticcheck U1000`) was available/permitted under the zero-spend/no-install constraint; findings here are limited to what direct `grep` cross-referencing could confirm (G-5).
- **G-8's "0 domain-layer key access" is a grep-based negative** (`Metadata[`, `RawExtras[`, `Attributes[`, `ProviderEvidence[` patterns only) — a differently-named local variable holding the same map value inside `domain/` would not be caught by this pattern.
- **Package-size "largest by LOC/exported-symbol-count" is descriptive, not a verdict** on whether `mercado_livre`'s adapter package or the composition root should be smaller — PHASE-0 reserves that judgment for the synthesis step.
