Decisions that define the platform

Os rails que D6/D7/implementation não podem reinterpretar por conveniência.

Product boundary

  • MPC = internal Marketplace Operations Control Plane.
  • Product 1.0 = Marketplace Operations + Commercial Intelligence.
  • Mercado Livre e Sankhya são primeiros proof systems, não a ontologia.
  • Human-controlled by default; automation só sob policy/authority explícita.

Identity

  • Organization = canonical tenant/isolation root.
  • MPC-owned IDs são opaque, stable, non-reusable.
  • Product fica externo: SourceInstance + native Product key.
  • Listing/Sale/Shipment permanecem source-qualified; sem mirror IDs por estética REST.
  • Principal diferencia human / automation / system.

Communication

  • Q = current owner meaning.
  • C = request owner capability.
  • E = committed producer fact with independent reaction.
  • P = read-only composition, zero-P baseline até D6 consumer proof.
  • accepted ≠ completed ≠ externally applied ≠ converged.

External integrations

  • Consumer owns meaning; adapter owns protocol.
  • Provider notification = pointer/acquisition evidence; authoritative reread establishes current meaning.
  • Sankhya target = sanctioned API Gateway; no Direct Oracle fallback.
  • Provider DTO/status/auth/pagination stay adapter-local.
  • 2xx never proves convergence.

Listing / Price / Availability

  • ListingIntent is one create/edit authoring identity.
  • Price is always PriceIntent, including initial publication.
  • Availability remains separate authority.
  • FOLLOW_SOURCE | EXPLICIT_OVERRIDE only.
  • D4 may jointly serialize owner-issued values without merging owners.

Economics

  • Components-first; missing cost/tax/fee/shipping never becomes zero.
  • L0 expected basis, L1 order economics, L2 realized occurrences.
  • R1/R2 reconciliation is Economics meaning, not generic Reconciliation entity.
  • Economic Attribution can be exact/partial/ambiguous/unresolved.

API / wire

  • Semantic Product API under Organization scope.
  • OpenAPI will be the single machine-readable wire authority.
  • No /v1 compatibility tax without a real entitled consumer.
  • Owner-specific custom methods when CRUD would lie.
  • If-Match only when literal request target is the protected resource; custom methods carry typed etag.

Collections W3-A/B

  • Named owner collection responses; no Page<T> / generic metadata.
  • Forward opaque cursor with limit/cursor/next_cursor.
  • No total_count, offset/page baseline or caller-selectable arbitrary sort.
  • Typed operation-specific filters; AND only; no generic query DSL.
  • SearchSourceProductsForMarketplace is true search, not a hidden Product List.

Non-negotiable invariants

Se implementation só funciona quebrando um destes, reabra a decisão responsável.

One business meaning → one authorityDuas authorities para o mesmo meaning são presumidamente erradas até prova em contrário.
Mechanism ≠ AuthorityRetry, cache, serialization, scheduler, projection ou adapter não ganham business meaning.
Unknown ≠ zeroUnknown ≠ Known(0) ≠ Empty ≠ Absent ≠ NotApplicable.
Provider 2xx ≠ convergenceAcceptance, effect, authoritative reread e convergence são axes separados.
No blind retry after ambiguous possible acceptanceReconcile primeiro; intake idempotency não autoriza redispatch externo.
Go backend is canonical business executionReact/TanStack é client, não segunda authority.
Organization scope is explicitTenant scope não é inferido de provider account, Selling Entity ou processo global.

W3-C — Cursor Validity / Population Change / Deduplication / Limits / Problem Grammar

Candidate direction

  • Stable Product identity/key appears at most once per traversal.
  • No global snapshot guarantee; population changes can affect unseen members.
  • `invalid-cursor` → 400; `cursor-expired` → 400; never silent restart.
  • Provider continuation expiry may be reconstructed only if same Product continuation semantics are preserved.
  • Transient provider outage ≠ cursor expiration.

Candidate refinements

  • List item projection may be smaller than point Get representation.
  • No generic fields/select/expand projection DSL.
  • Positive finite limit/default/max semantics; exact numbers deferred safely to final OpenAPI contract after list-item shapes exist.
  • No fabricated ComparableOffer ID only for deduplication.
  • Whole-W3 adversarial coherence review comes after W3-C ratification.

Important: esta seção é candidate work, não authority. W3-A e W3-B estão aceitos in-stage; W3-C ainda precisa de ratificação.

Stage details

Resumo navegável. Para decisão exata, abra o authority document.

D0 — Product / System Definition · CLOSED
Marketplace Central é o internal Marketplace Operations Control Plane. Product 1.0 = Marketplace Operations + Commercial Intelligence. Loop: observe → understand → reconcile → decide/policy → execute → verify → audit/reconcile. External systems retain facts inherently theirs.
D1 — Domains / Boundaries · CLOSED
Twelve semantic authorities. One meaning → one authority. Policy remains domain-owned; Governance only authorization semantics. Work owns actionable lifecycle, never originating truth.
D2 — Identity / Tenant / Data Ownership · CLOSED
Organization is tenant root. MPC IDs opaque/non-reusable. Product external via SourceInstance + native key. Listing/Sale/Shipment external/source-qualified. Principal human/automation/system.
D3 — Communication / Events · CLOSED
Q current meaning, C owner capability, E committed fact + independent reaction, P read-only composition. No event-per-state-change. Cross-owner atomicity is not invented.
D4 — External Integrations · CLOSED AS A WHOLE
Consumer owns meaning; adapter owns protocol. Notifications trigger reread, enumeration coverage is operation-scoped, 2xx does not equal convergence, ambiguous possible acceptance is not blindly retried. Sankhya target = Gateway only.
D5 — API · ACTIVE
Semantic Product API, Organization paths, source-qualified external identities, RFC 9457 problems, explicit idempotency/precondition semantics. W1/W2 canonical. W3-A/B accepted in-stage. W3-C is next/current candidate.
