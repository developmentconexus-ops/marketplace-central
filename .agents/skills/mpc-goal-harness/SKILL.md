# Marketplace Central Goal Harness

## Bootstrap

Read the compact root bootstrap, then the active M-08 execution guide. Compile
and validate the feature context pack before reading any selector. The pack is
the read authority: a route gap blocks targeted discovery rather than allowing
an unbounded scan.

## Goal flow

1. Reconcile the goal with mission, milestone, feature, accepted base, allowed
   paths, shared seams, and stop conditions.
2. Resolve registered knowledge-route IDs and compile the hash-current pack.
3. Select one owner and a Global-Maximum plan: owner, interfaces, consumers,
   legacy decision, unknown-state policy, risk, and proof.
4. Acquire one checkout/seam lease. Worktrees are optional Git coordination,
   not an environment boundary.
5. A visible milestone task may dispatch built-in **depth-one** subagents only.
   Prompts must name objective, selectors, paths, seams, gates, stop conditions,
   and compact output fields. Recursive fan-out is rejected.
6. Select only registered command IDs from the risk policy. The impact gate
   resolves structured argv; plans never execute command text.
7. Persist checkpoint ID (canonical), commits, paths, evidence, blocker, and
   next action. A native task/thread ID is optional correlation metadata only.
8. Resume from checkpoint plus MNFS/Git/pack artifacts. If task controls are
   unavailable, use the labelled **fresh-session fallback**; do not claim parity.

## Native capability boundary

Tasks, built-in subagents, read/steer/interrupt controls, and worktrees are
**operator-observed** capability evidence, not a repository-persisted API.
This skill does not create custom agents, hooks, app servers, or automations.

## Evidence and handoff

Use target labels faithfully. Fake/fixture validation proves deterministic
contract behavior only; named real QA is required only when the selected L3
contract requires it. Return only `status`, `checkpoint_id`, `commit`,
`changed_paths`, `evidence`, `review`, `blockers`, and `next`.
