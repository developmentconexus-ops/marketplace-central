### input view types (market-owned — see D-F3-a)
```go
type LocalProductIdentity struct {
    Codprod string  // canonical SKU (TGFPRO.CODPROD) — becomes MatchDecision.ProductID
    Descr   string  // description/title, for fuzzy ranking + hard-negative token extraction
    EAN     *string // GTIN; nil/empty ⇒ treated absent (caller validates checksum upstream)
    RefForn *string // manufacturer reference (TGFPRO.REFFORN)
    Marca   *string // brand (TGFPRO.MARCA)
}
type IdentityCandidate struct {
    CatalogProductID string
    Title            string
    Attrs            []IdentityCandidateAttribute
}
type IdentityCandidateAttribute struct {
    ID        string  // e.g. "GTIN","BRAND","MODEL"
    Name      string
    ValueName *string
}
```
Candidate identity values are read from `Attrs` by ID: EAN ⟵ `GTIN`; marca ⟵ `BRAND`; refforn ⟵ `MODEL` (also accept `REFERENCE`/`SELLER_SKU`? NO — only `MODEL`; flag if a fixture needs more). Missing/null attr ⇒ that signal absent.

### the gate (bind EXACTLY — IC-01 §Matching Gate)
Evaluate EACH candidate independently, then select:
- **Anchors** (independent agreeing signals; each counts at most once): `ean` (local.EAN present & equals candidate GTIN, normalized), `marca` (both present & equal, normalized), `refforn` (both present & equal, normalized). **Title fuzzy is NEVER an anchor** — it only RANKS (breaks ties / orders candidates). Record agreeing anchor names in `Anchors` (lowercase, stable order `["ean","marca","refforn"]`).
- **Contradictions** (hard-negatives — "contradição vence EAN", REJECT even with equal EAN): divergence between local and candidate on any class — `kit` (kit/combo vs unit), `cor` (color), `medida` (measure/dimension/size), `voltagem` (voltage, e.g. 127V vs 220V), and `marca` (both brands present & DIFFERENT — this is the Doka/Menegotti + Doka/VW collision mechanism). Extract class tokens deterministically from `Descr`/`Title` + attrs (see D-F3-d). Record diverging class names in `Contradictions`.
- **Per-candidate classification:**
  - contradiction present ⇒ candidate REJECT-classified.
  - else EAN present-and-agrees AND ≥1 more anchor (marca or refforn) agrees ⇒ ACCEPT-qualifying.
  - else ⇒ REVIEW-classified.
- **Selection → overall MatchDecision:**
  - no candidates ⇒ `NO_CANDIDATE`, band `BAIXA`, `CatalogProductID=nil`, empty Anchors/Contradictions.
  - ≥1 ACCEPT-qualifying ⇒ `ACCEPT`; choose highest-scoring qualifying (title-fuzzy tiebreak, then stable input order).
  - else ≥1 REVIEW-classified ⇒ `REVIEW`; choose highest-scoring.
  - else (all candidates contradicted) ⇒ `REJECT`; choose highest-scoring contradicted candidate (so its contradictions are surfaced).
  - `CatalogProductID` = pointer to the chosen candidate's id (non-nil for ACCEPT/REVIEW/REJECT). `Anchors`/`Contradictions` = the chosen candidate's.
- **EAN-absent cap (D-F3-b):** if local.EAN absent, overall status is capped at `REVIEW` (never ACCEPT) regardless of anchors.

### band scoring (deterministic; thresholds are CONTRACT-FIXED, weights are chip-decided D-F3-c)
Per chosen candidate: score = `ean?50` + `marca?20` + `refforn?20` + `round(titleFuzzy*10)` (titleFuzzy ∈ [0,1]; capped ≤10 so title alone never reaches 50). Map by IC-01 thresholds: **≥85 ⇒ ALTA · 50–84 ⇒ MEDIA · <50 ⇒ BAIXA**. NO_CANDIDATE ⇒ BAIXA (score 0). A REJECTed candidate still gets a band from its score (evidence), but status REJECT dominates.
