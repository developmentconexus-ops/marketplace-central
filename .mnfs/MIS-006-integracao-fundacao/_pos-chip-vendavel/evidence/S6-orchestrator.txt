4. FINDING — the new optional port is asserted at 1 of 5 seats, and the 4 missing seats
   fail SILENTLY (major; transferred to S9 as a named criterion, not a defect in S6)

   S6 introduced ports.CatalogAssortmentReader (ports/catalog_page.go:117). Measured:

     implementers, whole module, tests included ... exactly one: oracle.Reader
     compile-time asserts for CatalogAssortmentReader ... exactly one:
         oracle/catalog_page.go:312
     compile-time asserts for the SIBLING port CatalogPageReader ... five:
         oracle/catalog_page.go:311, routing/reader.go:159, cache/cache.go:312,
         observability/timing.go:136, application/service.go:66

   The live chain composed in composition/root.go:449→453→479 is
   oracle.Reader → cache.NewReader → observability.NewTimingReader → routing.NewReader.
   Each seat forwards the port it knows by a RUNTIME assertion, and routing's failure
   branch is not a compile error but an error value:

     routing/reader.go:151  pager, ok := rd.(internalreadports.CatalogPageReader)
     routing/reader.go:153  ReadErrorSourceUnavailable, "active source's reader does not
                            support catalog paging"

   ReadErrorSourceUnavailable is a 503 on the screen. So a decorator that does not
   implement the new port does not fail to build — it deletes the capability and reports
   the source as unavailable. That is the exact mechanism of the catalog-503 defect built
   once already in CHIP-M02, whose recorded lesson was compile-time asserts for EVERY
   optional port.

   S6 is not at fault for the four missing seats: the decorators are outside its write-set,
   and an assert on a type that does not yet implement the interface is a build failure,
   i.e. it would drag S9's work into S6. What S6 owed, and did not leave, was the condition
   written where the next writer will stand.

   Disposition — glue at my seat, F-3 technique, in a file already in the write-set: the
   condition is now a comment on the interface declaration. It names the four seats by
   name, names the 503 mechanism, requires an arrival test that reads the count THROUGH the
   composed reader from composition/root.go rather than off the Oracle reader, and forbids
   the shape that would hide the problem — a runtime `.(CatalogAssortmentReader)` with a
   fallback at the HTTP seam, which converts a missing seat into a quiet wrong answer
   instead of a build error.

   This is the same failure family as the two hops S5B fixed and the third site A-16 ruled
   on: a value that leaves its source and is never asserted to ARRIVE. Here the value is a
   capability rather than a column, and the missing arrival test is S9's to write.
