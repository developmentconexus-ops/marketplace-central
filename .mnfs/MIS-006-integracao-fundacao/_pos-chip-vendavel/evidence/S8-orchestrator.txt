5. FINDING F-4 — THE CONTRACT DESCRIBES A BODY AND A STATUS THE SERVER CANNOT EMIT
   The new endpoints declare their errors as `$ref: '#/components/schemas/ErrorResponse'`, which
   is the nested shape `{"error": {"code": ..., "message": ...}}`.

   S10 puts the sellable-assortment handler in
   `apps/server_core/internal/modules/tenant_config/transport/http_handler.go` — the SAME file
   that already serves `/config/active-source`. I read what that file actually writes:

     func writeError(w http.ResponseWriter, status int, code, message string) {
         payload := map[string]string{"error": code}
         if message != "" { payload["detail"] = message }
         httpx.WriteJSON(w, status, payload)
     }

   FLAT — `{"error":"invalid_body"}`. That is `ActiveSourceError`'s shape, and it is why the
   neighbour twin `/config/active-source` refs `ActiveSourceError` and why its own test asserts so.

   Three false statements in the published contract, then:
     (a) GET declares `"404"` — the handler has NO not-found branch at all. Its error statuses are
         400 (`unknown_erp_source`, `invalid_body`, `invalid_active_source`) and 500
         (`internal_error`). Under A-17 the default for an absent tenant row is resolved at the
         load seam, so GET returns defaults and can never 404.
     (b) GET's 404 body is the nested shape. The handler cannot produce it.
     (c) PUT's 400 body is the nested shape. The handler cannot produce it.
   And one omission: no `"500"` is declared on either operation, though `store.Get` failing is a
   certain path through the same handler.

   `ErrorResponse` appears 109 times across this spec, so it is not deprecated in general. What is
   true is narrower and measurable: the last `ErrorResponse` reference before `/erp/imports:` is at
   line 3184, and the region 3186→3422 was deliberately free of it — both families living there
   (`erp_import`, `tenant_config`) emit flat errors. The erpImport guard's over-broad window is
   what made it the tripwire, but what it caught is TRUE. An alien test caught a real defect by
   accident of file ordering, and the correct response is to fix the defect, not the window.

  GET /config/sellable-assortment:  "404" + nested ErrorResponse  ->  "500" + SellableAssortmentError

  than softened: the handler has no not-found branch, and under A-17 an absent tenant row resolves
  to defaults at the load seam, so GET cannot 404. A false statement in a published contract is
  deleted (R-25).

  The enum is minimal by measurement, not by guess: those are the two codes this handler's shape
  can produce for these two operations. If S10 measures a need for a third, it amends then.
