3. FINDING F-1 — THE FUNCTION DID NOT DIE; IT WAS EXPORTED AND MULTIPLIED
   Hub, verbatim: "nenhum caminho pode sobrar chamando `defaultSellableAssortment()` — a função
   morrer é critério, não sugestão."

   What shipped: the lowercase private helper is gone and `ports.DefaultSellableAssortment()` was
   born at `ports/catalog_page.go:96`, returning a hardcoded
   `{OnlyRevenda:true, OnlyEmEstoque:true, OnlyEcommerceEligible:true}`. Call sites went from one
   to eleven — seven of them production:
     catalog/transport/http_handler.go:251, :263, :276

     erp_import/adapters/internalread/reader.go:375, :386
   That is a rename, not a death, and the REASON the hub wanted it dead — one place owns the
   default — is more violated after the slice than before it.

   And the name is false, which I can measure rather than argue. `tenant_config/repository.go:31`:
     // Get returns the tenant's active-source Config, or ErrUnknownActiveSource if
     // the tenant has no row (fail-closed — never a silent default).
   A tenant with no row gets an ERROR, not a default. So this system has no default sellable
   assortment. A constant named `DefaultSellableAssortment` that is never any tenant's policy, and
   that routing discards on every composed call, is a total claim the code does not honour — the
   R-24/R-25 class, where the fix is deletion rather than softening.

   Live blast radius today: none. Below routing, `oracle/catalog_page.go:22,41,164` and
   `internalread/reader.go:375,386` hand that hardcoded {true,true,true} STRAIGHT to the query
   builder with no tenant override, but routing only ever calls the WithPolicy variants, so no
   composed path reaches them. It is a loaded landmine, not a live wound: the next caller that
   reaches an adapter's base-port method filters the catalog by a rule no tenant ever authored.

4. FINDING F-2 — THE BOOLEAN CAME BACK WEARING A STRUCT (class-level, A-20)
   `routing/reader.go:181-183`:
     if requested == internalreadports.AllProductsAssortment() {
         policy = internalreadports.AllProductsAssortment()
     }
   `AllProductsAssortment()` is the ZERO VALUE. So `requested` — a parameter typed as a policy and
   named for one — is read exactly once, as a three-bit equality test against zero, and then
   discarded. Transport encodes a wire boolean into a policy struct; routing decodes it back into a
   boolean and throws the rest away.

   A-18's condition is met in FORM: only a policy crosses the port. It is not met in SUBSTANCE:
   the receiver still recovers `include_all` from it, so the two-mechanisms-that-must-agree shape
   is intact, with the agreement now enforced by struct equality instead of a bool.

   The concrete cost is a false affordance, and the next slices are the ones who pay it: the
   signature invites a caller to pass a real policy through `...WithPolicy`, and routing will
   silently ignore it unless it happens to equal the zero value. S11/S12 wire "ver todos"; that is
   exactly the caller this trap is aimed at.

   Under the new profile rule this is not one finding, it is the SECOND instance of a class already
   paid for in this chip: `IncludeAll` travelling beside the policy was the first, and A-17/A-18
   were written to kill it. The rule says the line stops here rather than taking another point fix.

   Both findings share one root: there is no honest way at this port to say "use the tenant's
   stored policy", so a magic value was invented to mean it.

5. RECOMMENDATION (measured, minimal, not applied)
   Make the request optional instead of magic — `requested *SellableAssortmentPolicy`, where nil
   means "the tenant's stored policy" and non-nil means "exactly this". One mechanism; no coupling
   to the zero value; no constant claiming to be a default that is not one; and a caller that
   passes a real policy is honoured instead of silently dropped. Transport keeps `include_all` at
   its seam: absent or `false` -> nil, `true` -> `&AllProductsAssortment()`. `DefaultSellableAssortment()`
   is deleted, which is what the criterion asked for, and the adapters' base-port methods stop
   fabricating a policy they have no authority to invent.
